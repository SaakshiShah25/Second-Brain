# MyConfía: findings from the first full test and eval run (28 Oct 2026)

These findings come from the generated report, [2026-10-28-test-report.md](2026-10-28-test-report.md), which has every number and case. This page draws the conclusions from it.

## Bottom line

- **The app works.**
  - All 155 backend tests and 17 frontend tests pass.
  - Intent routing, the safety check, questions and the load tests score 100%: 32/32, 14/14, 9/9 and 7/7.
- **The capacity limit is not Groq. It is Cohere's trial key** (1,000 calls a month, shared by everyone). It allows about **3–5 active users**.
  - Fix that, and the next limit is Groq: about **20–25 active users a day** under today's monthly caps.
  - At any single moment, about **2 captures or 2 questions per minute** across all users.
- **Extraction quality is the weakest area**, at 4/8 cases. The usual problem is that a note's points repeat its to-dos, or a "they owe me" commitment is missed.
- **The tests found and fixed 5 real bugs,** listed below. Every fix has a regression test, so it can't come back unnoticed.

## Bugs found and fixed in this run

| Bug | Impact | Fix |
|---|---|---|
| The default rate limit never applied. slowapi's middleware can't see FastAPI's included routers, so every route was treated as exempt. | Any user could flood every endpoint except chat and voice. | The limit is now a dependency on every router: 60 per minute, per user, per route. The load test confirms 60 allowed, then 429. |
| A new user's first screen could fail with 500s. Settings and initiatives both "create defaults on first read" and raced each other. | 7 of 100 requests failed with 5 concurrent new users. | If the insert hits "already exists", the other request's row is read back. Now 0 errors at 10 concurrent users. |
| Deadlines written as "by Friday", "before…" or "EOD…" didn't become dates. | Tasks were silently saved with no due date. | The date resolver now accepts that wording (12 test cases). |
| Trivia questions ("who won the 2011 world cup") were saved as notes. | Junk notes, and wasted extraction tokens. | Question forms stay out of scope; the to-do guard only protects statements. |
| AI and Cohere calls made by the agent's worker threads weren't attributed to the user or request. | The admin page and capacity numbers overstated capture cost (Cohere counted at 5 calls per capture instead of 2). | The request context is now copied on the calling thread. |

## How many users? (measured)

### What each action costs

| | Groq 120b | Groq 20b | Safeguard | Cohere |
|---|---|---|---|---|
| **One capture** | 3,600 tokens | 620 | 750 | 2 calls (embed + search index) |
| **One question** | 1,900 tokens | 2,700 | 750 | 3 calls (embed + rerank + search) |

### Free-tier limits that matter

| Limit | Free tier |
|---|---|
| Groq | 200K tokens/day per model, 8K tokens/minute per model (Groq's own headers), 1,000 requests/day |
| Safeguard model (safety check) | 2K tokens/minute and ~3 requests/minute; falls back to 20b when exceeded |
| Cohere trial | 1,000 calls/month, for everything |
| Supabase | 500 MB database, about 23 KB per note including search vectors (≈ 21,000 notes) |

### Active users supported

Today's caps are 50 captures and 50 questions per user per month, which is about 1.7 of each per day.

| Constraint | Light user (2 captures + 1 question/day) | Regular user (5 + 3), with caps | Regular user (5 + 3), no caps |
|---|---|---|---|
| **Cohere 1,000 calls/month** | **5** | **3** | **1** |
| Groq 120b tokens/day | 25 | 21 | 8 |
| Supabase 500 MB (a year of notes) | 35 | 35 | 11 |
| Groq 20b tokens/day | 53 | 36 | 17 |
| Supabase egress 5 GB/month | 500+ | 200 | 200 |

**At the same moment:** about **2.2 captures per minute** for everyone combined. The binding limit is Groq 120b's 8K tokens per minute, against 3.6K per extraction. A third person capturing in the same minute waits or sees the "AI is busy" message, and their text is put back in the box.

### Decisions this supports

1. **Raise the Cohere limit first.** It's the only thing holding you at single-digit users. Options, cheapest first:
   - **Drop the duplicate embedding at capture.** The note is embedded once for the old `interaction.embedding` column, used only by the older fallback search, and again by the search index. Removing the first takes captures from 2 Cohere calls to 1; the fallback would then search by keywords only.
   - **Turn off reranking on the free tier** (`COHERE_RERANK_DAILY_CAP=0`). Questions go from 3 calls to 2, at a small cost in answer ordering.
   - **Ask Cohere for a production key.** It's pay-as-you-go and cheap at this volume, but it isn't free.

   With the first two changes, Cohere stops being the bottleneck at around 10 light users.
2. **After that, invite up to about 20 users** with the current caps. Groq 120b is then the limit, at about 21–25 active users a day.
3. **Keep the monthly caps.** Without them, Groq alone supports only about 8 regular users (5 captures and 3 questions a day). The caps are what make 20+ users possible on the free tier.
4. **The 2-per-minute burst limit matters more than the daily limit for a group demo.** Ten people trying it in the same minute will see waits. Stagger demos, or move extraction to the 20b model, which has its own 8K per minute.
5. **Storage isn't a concern this year:** 35+ users can each save a year of notes within 500 MB.

## Quality findings (the AI's behaviour, not code bugs)

| Area | Result | What's wrong |
|---|---|---|
| Intent routing | 32/32 | Includes imperative to-dos, Hinglish, venting and trivia. No real note was refused. |
| Safety check | 14/14 | No real notes blocked (venting, health, money); all injection, weapons, malware, fraud and hate blocked. The safeguard model hit its 3-per-minute limit during the run, and the 20b fallback judged correctly. |
| Questions | 9/9 | Facts present, nothing invented (the "crypto" question correctly says there are no such notes). One answer still showed an internal id as "(task 62)". |
| Initiative pages | 9/10 | Good sections (Thesis, Valuation, Risks…) and every key fact kept. One to-do appeared as a point, inherited from a note whose points included it. |
| **Extraction** | **4/8** | (1) Points repeat the to-dos in 2 notes, against the prompt. (2) A "they owe me" commitment ("he'll get back to us next Monday") is missed, in every run so far. (3) One task lost its deadline. (4) A note about valuation without the words "IC" or "case study" was filed under Work. |
| Captures (end to end) | 2/3 | Saved under the right initiative with deadlines resolved. "Ask Priya to send … by Friday" became a "Priya owes me" task. That's arguably fine; the dataset expected "I owe". |

**Recommended next step for quality:** tighten the extraction prompt on two rules (never put a to-do in the points; always extract what others promised), then re-run `--only extraction` to confirm. Each extraction re-run costs about 30K tokens on 120b.

## Reliability notes

- **Speed:** opening the app (4 API calls) takes p50 0.5–0.9 s and p95 1.1–3.0 s with 1–10 users at once on a laptop. The Notes screen with 1,000 notes loads in 1.9 s (545 KB). Render's free plan has far less CPU, so expect it to be slower there. Re-run the load test against the deployed URL once it's live.
- **Memory:** about 60 MB under load, well inside Render's 512 MB.
- **Two requests stalled for 25–35 minutes** during the overnight runs, after Supabase reads timed out and the connection was reset. That looks like the laptop sleeping or losing network, not the app. But it does show the database client has no short timeout, so one hung call can hold a server thread. **Recommendation:** set a 10–15 s timeout on the Supabase client.
